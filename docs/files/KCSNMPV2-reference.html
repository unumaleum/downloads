Exeltech KC SNMP MIB reference

Exeltech Software Downloads · Download KCSNMPV2.mib

KCSNMPV2.mib describes what the monitor card of an Exeltech KC power system reports over SNMP, and the settings an SNMP manager can change. This page lists every object and trap in it, with its full OID, and what to watch for.

Using the MIB

  • Load it into your SNMP manager or MIB browser. It imports RFC1155-SMI, RFC-1212, RFC-1215 and SNMPv2-TC, which managers usually have already. Its comment says it was validated with Muonics' smicheck.
  • Every object is a scalar: read it with the instance .0, for example 1.3.6.1.4.1.30320.2.0.1.1.0 for the battery voltage.
  • Communities: StatusBoost reads with public and writes with private, over SNMP v2c on UDP port 161.
  • Traps go to the trap managers set in trap-target-ip1 to trap-target-ip3.
  • Many settings are easier to change in StatusBoost: its Network Feature Setup sets the trap managers, the network settings, SNTP and the all-good trap. The alarm configuration is set with StatusBoost's System Configuration or the Alarm Configuration Tool.

Known issues

  1. Utility or inverter: the phase objects' names and descriptions disagree. Objects 1 to 3 of each phase are named utility…, but described as inverter values; objects 4 to 6 are named inverter…, but described as utility values. Which is right is being checked. Until then, compare a reading with what StatusBoost shows before relying on it.
  2. Bits 11, 12 and 13 of systemAlarms all read "Ph1 on Ref2" in the MIB. They are phase 1, phase 2 and phase 3 on Reference 2.
  3. Bits 1, 5 and 14 of systemAlarms have different names in the MIB and in StatusBoost: "Power Module Fail" and Module Overload Detected; "Module Local Disable" and Module Offline Detected; "NA" and Cage Not Detected. The table above shows both.
  4. slotAlarmtrap has the same description as generalAlarmtrap, "A general Status update". It carries slotAlarms, so it reports the module slots.
  5. The bit masks are signed. systemAlarms and the configuration objects are INTEGER, a signed 32-bit number, so a manager shows a value with bit 31 (Contactor Open Detected) set as negative. Read them as unsigned 32-bit numbers.

These are notes about the MIB's text. The MIB file is published as it is, so the object names and OIDs that managers already use stay the same.
